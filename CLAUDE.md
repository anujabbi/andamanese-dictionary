# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static HTML trilingual dictionary of **Great Andamanese (GA)**, an endangered language of the Andaman Islands. Entries are presented with GA in IPA, GA in Devanagari script, English glosses, Hindi glosses, audio pronunciations, and pictures.

The site is plain HTML/CSS/JS opened directly in a browser. The legacy frameset pages have no build step. A small Node.js script (`scripts/build-search-index.mjs`, zero dependencies, tested with `node:test`) regenerates `assets/search-index.json` when the lexicon content changes.

## History — formerly generated by Lexique Pro

The HTML files under `lexicon/`, `index-*/`, `categories/`, and `title.htm` were originally generated by Lexique Pro 3.6 on 2018-01-16 (see `<meta name="generator">` and `<meta name="date-generated">` in every page). **The Lexique Pro authoring tool has since been retired** — there is no upstream that could overwrite hand edits, so every file in this repo is safe to edit directly. The `lp*`-prefixed CSS classes and the `eN` entry-id convention are now project conventions to preserve for backward compatibility, not external constraints.

## How to view the site

Open `index.htm` in a browser. As of May 2026 the root index is a modern search-driven homepage that bridges into the legacy frameset pages via autocomplete; the legacy `lexicon/index.htm` frameset still works directly. Both run under `file://`, `python -m http.server`, and GitHub Pages.

The live site is published to GitHub Pages at https://anujabbi.github.io/andamanese-dictionary/ from the `main` branch root.

## Architecture

The site is built around HTML framesets (a deprecated but Lexique-Pro-canonical layout). Four parallel views all share the same top menu (`title.htm`) and the same underlying entry pages in `lexicon/`:

- `lexicon/` — main entries, one HTML file per IPA letter, numbered `01.htm` (ɑ) through `35.htm`. Each entry has a stable id of the form `eN` (e.g. `<span id="e13">`). Cross-references between entries use anchors like `01.htm#e13`. `lexicon/index.htm` is the frameset that hosts the letter-bar + entry pane.
- `index-english/`, `index-hindi/`, `index-ga_in_sript/` — reverse-lookup indexes. Each is a frameset with an alphabetical link bar (`alphalinks.htm`), an index pane (`NN.htm`), and a content pane that loads the corresponding `lexicon/NN.htm#eN`. Index links call `go(a,b)` in `javascript/index-go.js`, which navigates `parent.basefrm` to the lexicon entry and triggers fragment highlight.
- `categories/` — semantic categories (`c001.htm`–`c124.htm`) browsed via a JS tree (`tree.htm` + `javascript/categoryNodes.js` + `ftiens4.js` treeview library + `ua.js` UA sniff).
- `audio/` (~745 `.wav`), `pictures/` (~381 image files) — referenced from lexicon entries via relative paths like `../audio/<filename>.wav` and `../pictures/<filename>`. **Filenames contain spaces** (e.g. `Angered person-ErcEktutbolo_Nu.wav`); they are URL-encoded in HTML and decoded back by `BatmoAudioPop.js`.
- `images/` — small UI icons only (folder-tree glyphs, sound-icon).
- `stylesheets/lexiquepro.css` — the only stylesheet; all `lp*`-prefixed classes come from here.

## JavaScript pieces

Each script is single-purpose and globally scoped (no modules, no build):

- `javascript/BatmoAudioPop.js` — opens a popup window with an embedded `<object>` Windows Media Player to play `.wav` pronunciations. Sniffs UA for Windows vs other to choose MIME type. (Modern browsers have largely removed plugin support; audio playback may not work in current browsers — flag this if the user reports broken audio rather than trying to "fix" the generated file.)
- `javascript/hi.js` — fragment highlighter (`fragHL`), adds `class="fragment"` to the entry pointed at by `location.hash` so the linked entry stands out. Wired in via `window.onload`.
- `javascript/index-go.js` — `go(letterFile, entryId)` used by reverse-index pages to jump into the main lexicon frame.
- `javascript/categoryNodes.js` — declarative tree of category nodes consumed by the `ftiens4.js` Treeview library.
- `javascript/ftiens4.js`, `javascript/ua.js` — third-party Treeview infrastructure + browser detection. Don't edit.

## Modern additions (May 2026)

- `index.htm` — modern search homepage. Replaces the original 7-line redirect.
- `about.htm` — about page in the homepage's visual language.
- `assets/home.css`, `assets/home.js` — homepage styles and behavior. Vanilla JS in a single IIFE, no modules.
- `assets/search-index.json` — compact JSON index (~3,700 entries) consumed by the homepage's autocomplete. Generated; **re-run `node scripts/build-search-index.mjs` after editing any `lexicon/*.htm` content** so the autocomplete stays in sync.
- `scripts/build-search-index.mjs` + `scripts/tests/` — Node ESM parser with `node:test` coverage.
- `scripts/fix-media-refs.mjs` — repairs `../audio/` and `../pictures/` references that don't match the file on disk (the checked-in media files spell apostrophes as `_`). Idempotent; `--dry-run` reports without writing.
- `stylesheets/lexiquepro.css` — was the original Lexique Pro stylesheet; in May 2026 the homepage palette/typography (paper background, Georgia serif headwords, terracotta accent) was applied to it. Sizes, weights, margins, and layout were left untouched.

Autocomplete results navigate to `lexicon/NN.htm#eN` — clicking a search hit lands the user inside the existing frameset experience, where `javascript/hi.js` highlights the entry's anchor.

## Editing conventions

- Preserve the exact CSS class names (`lpLexEntryName`, `lpGlossEnglish`, `lpGlossHindi`, `lpGlossGA_in_Sript`, `lpCategory`, `lpExample`, etc.) — `lexiquepro.css` is the only thing styling them.
- Keep the `id="eN"` numbering stable. Cross-references across files, the reverse indexes, and `assets/search-index.json` all hardcode these anchors; renumbering one entry silently breaks links everywhere.
- After editing `lexicon/*.htm`, re-run `node scripts/build-search-index.mjs` to refresh the search index. The parser may need updating if you change the HTML structure (it's regex-based on the `lp*` class conventions).
- Treat character encoding carefully: pages declare `charset=UTF-8` and contain IPA (ɑ, ɛ, ɖ, ʈʰ, ŋ, ɲ…) plus Devanagari. Don't let editors re-save as Windows-1252.
- When referencing audio/picture files with spaces in their names, use `%20` in HTML attributes.
- An entry's picture lives in the `<p class="lpPicturePara">` **before** its entry paragraph, and its pronunciation in an `<a href="../audio/…">` before the headword span. Both conventions are load-bearing: `assets/cards.js` (`pictureBefore`) and `scripts/build-search-index.mjs` (the `pic` field) pair media to entries by that ordering, and every tab — Lexicon a–z and देव, the three reverse indexes, Categories — renders from one of those two paths.
- Category tags are cross-references, not labels. Every `lpCategory` string matches exactly one `name` in `assets/category-list.json` (c001–c062 English, c063–c124 their Hindi equivalents), and `cards.js` turns each into a link to `categories/index.htm#cNNN.htm`. Adding a category string that isn't in that list silently produces an inert chip — regenerate the list rather than inventing a tag.
- The `Etym` and `Environmental` tags on a card drive the header's Show filter through `GAChrome.setEtymSource` / `GAChrome.setFilter` (both toggle off on a second click). They render as plain text on pages that don't load `chrome.js`, which `cards.js` detects via `window.GA_PAGE` — not via `window.GAChrome`, because deferred scripts run with `readyState` already `interactive`, so `cards.js` renders its cards before `chrome.js` has executed.
- The reverse-index sidebars fold rows that share a term into collapsible gloss
  groups, but **only where the term is a gloss** — the `group: true` flag is set
  on the English and Hindi *native* modes in their `index.htm`, and must never be
  set on a list of headword forms (the GA-script list, or any `देव` / `a–z`
  alternate mode), where repetition means homographs rather than shared meaning.
  See `docs/adr/0002-reverse-index-grouping.md`.
- Media paths differ by source: page markup stores them relative to the page's own directory (`../audio/x.wav`), while `search-index.json` stores them repo-root relative (`audio/x.wav`). Anything rendering index-sourced entries must prefix `GA_PAGE.base`; anything rendering fetched markup should pass it through `GACards.rebaseEntryMedia` / `GACards.mediaPath`.
