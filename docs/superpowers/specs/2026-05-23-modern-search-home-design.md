# Modern Search Homepage — Design Spec

**Date:** 2026-05-23
**Status:** Draft for implementation

## Background

The Great Andamanese (GA) trilingual dictionary is a static HTML site generated by Lexique Pro 3.6 in January 2018. Today the root `index.htm` is a 7-line JavaScript redirect to `lexicon/index.htm`, which loads a deprecated HTML frameset with a top menu (`title.htm`), a letter bar, and a body pane for the current letter's entries. Reverse-lookup indexes for Devanagari, English, and Hindi each live in their own frameset.

The site is a meaningful preservation record of an endangered language. The current UI feels like the early-2000s desktop-only export it is, with no search and no mobile consideration.

## Goal

Replace the redirect home with a single, modern, Google-like search homepage that:

- Lets a user search the dictionary by typing English glosses or GA-in-IPA headwords.
- Surfaces a rich autocomplete dropdown that previews each candidate entry.
- Routes the user into the existing Lexique Pro pages for the full entry view — the existing frameset experience is preserved.
- Reads as a serious, editorial homepage befitting a preservation project, not a generic tech UI.
- Works on phones.

Nothing in `lexicon/`, `index-english/`, `index-hindi/`, `index-ga_in_sript/`, `categories/`, or `title.htm` is modified — those remain Lexique-Pro-owned generated output.

## Scope

**In scope:**

1. New homepage at `index.htm` (replaces the current redirect).
2. Autocomplete-driven search box on the homepage.
3. A static `search-index.json` built once from the existing `lexicon/*.htm` pages.
4. A small builder script that regenerates `search-index.json` whenever the Lexique Pro source is re-exported.
5. A new `about.htm` page (linked from the top-right of the homepage).
6. Word-of-the-Day card on the homepage.

**Out of scope:**

- Any edits to Lexique-Pro-generated files (`lexicon/*.htm`, `index-*/*.htm`, `categories/*.htm`, `title.htm`).
- A dedicated search-results page. Hitting Enter navigates straight to the top match's existing letter page (`lexicon/NN.htm#eN`).
- A new entry-detail view. Once the user opens an entry, the existing frameset experience is what they get.
- A "back to home" link injected into the existing pages. Users return via the browser's back button.
- Hindi-language and GA-in-Devanagari input. The search box accepts English and GA-in-IPA only. Hindi and Devanagari glosses are still *displayed* in autocomplete rows.
- IPA on-screen keyboard. Users who want to type IPA either paste it or use OS-level input. Plain-Latin transliteration → IPA fuzzy matching is *not* in scope for v1.
- Categories browsing as a redesigned tree. The "Categories" nav link still opens the existing `categories/index.htm`.

## User experience

### Homepage

Layout, top to bottom, centered:

1. **Top-right:** small uppercase "About" link.
2. **Brand:** serif headline reading "Great Andamanese".
3. **Tagline:** italic serif subtitle reading "A trilingual record of an endangered language".
4. **Search box:** rounded pill, placeholder "Search a word in English or IPA…", with a search-glyph icon on the left.
5. **Browse links:** five inline links, dot-separated on desktop, 2-column grid on mobile:
    - **Lexicon** → `lexicon/index.htm`
    - **Devanagari index** → `index-ga_in_sript/index.htm`
    - **English index** → `index-english/index.htm`
    - **Hindi index** → `index-hindi/index.htm`
    - **Categories** → `categories/index.htm`
6. **Word of the Day card:** one entry per day, deterministically chosen from the date. Shows IPA headword + English/Hindi glosses, with an inline audio play button. Clicking anywhere on the card opens the entry in the existing frameset.

Approved mockup: `home-b-refined-v4.html` (visual companion session output).

### Autocomplete dropdown

Approved mockup: `autocomplete.html` → rich (two-line) variant.

**Trigger:** the search box has focus.

**Empty state** (focused, no query):
- Section labelled "Recent" lists the user's last 0–5 entries from `localStorage`.
- Section labelled "Try" lists 3 hard-coded suggested entries.
- If there is no recent history, the "Recent" section is omitted.

**Typing state** (≥1 character):
- Results filter the search index. Top 6 matches appear in the dropdown.
- Each row shows:
  - Line 1: IPA headword, then Devanagari headword.
  - Line 2: a small uppercase category badge, then the English gloss, "·", then the Hindi gloss.
  - Right-aligned: a circular audio button. Clicking the audio button plays the entry's `.wav` and stops event propagation (does not navigate).
- The matched substring within whichever field matched (IPA or English) is wrapped in `<mark>`.
- Below the rows, a footer shows keyboard hints (↑↓ navigate, ↵ open) and a "See all N results →" affordance that navigates to the top match's page (same as pressing Enter — see "No results page" below).

**No-results state:**
- Quiet message: "No matches for \"<query>\"". Sub-text: "Try a shorter prefix, or check spelling."
- A "Browse by letter →" link below, navigating to `lexicon/index.htm`.

**Keyboard:**
- ↑ / ↓ moves the active row.
- Enter on a row opens that entry; Enter with no active row opens the top result.
- Esc clears the active row but keeps the dropdown open. Esc again blurs the input.

**Mobile (≤640px viewport):**
- The dropdown appears immediately below the search box and matches the box's width.
- Audio buttons have a minimum 40×40 px tap target.
- The browse-links row and Word-of-the-Day card remain visible below; the dropdown overlays them.

### Click-through behaviour

- Clicking an autocomplete row navigates the top-level window to `lexicon/NN.htm#eN`. The user lands directly on the entry within its letter page (the Lexique Pro existing experience). The legacy `hi.js` highlights the `#eN` anchor on load.
- Clicking the audio button on a row plays the entry's `.wav` and does **not** navigate.
- Clicking a browse link navigates to the existing frameset index pages.
- Clicking the Word-of-the-Day card behaves like clicking an autocomplete row.

### About page

A new lightweight `about.htm` at the repository root. Same visual language as the homepage. Contents:

- Short statement about the dictionary, attribution to the original Lexique Pro source, and a note that the dictionary records an endangered language.
- Link back to the homepage.
- Caveat about audio: explains that some browsers no longer support the legacy plugin player and that audio may not work everywhere. (Per project memory `project_audio_works.md`, audio still works in modern browsers via native fallback — but we note the historical caveat anyway.)

This is the only acceptable place to fill in the project description; exact prose to be drafted during implementation in collaboration with the user.

## Architecture

### File layout

```
index.htm                         # NEW — modern homepage (replaces redirect)
about.htm                         # NEW — about page
assets/                           # NEW — all new front-end assets
  home.css                        # NEW — homepage + autocomplete + about styles
  home.js                         # NEW — autocomplete logic, recents, WOTD
  search-index.json               # NEW — generated; committed to repo
scripts/                          # NEW — build tooling
  build-search-index.mjs          # NEW — Node.js parser
lexicon/                          # UNTOUCHED — Lexique-Pro-owned
index-english/, index-hindi/, …   # UNTOUCHED
categories/                       # UNTOUCHED
title.htm                         # UNTOUCHED
javascript/, stylesheets/         # UNTOUCHED (Lexique Pro generated)
```

The `assets/` directory is deliberately separate from the Lexique-Pro-generated `javascript/` and `stylesheets/` directories, so it is obvious which files survive a regeneration.

### Frontend modules (in `assets/home.js`)

The file is a single ES-module-free script (the project has no build system, so we stay browser-native). Internally it has small, isolated units:

- **`loadIndex()`** — fetches `assets/search-index.json` on page load, returns a Promise.
- **`searchIndex(query, index)`** — pure function. Returns the top N matches plus the matched field and match span. No DOM, no state.
- **`renderDropdown(results, query, state)`** — pure-ish DOM renderer. Reads `state.activeIndex`. No side effects beyond writing to the dropdown DOM node.
- **`recentEntries()`** / **`recordRecent(entryRef)`** — localStorage wrappers.
- **`wordOfTheDay(index, dateStr)`** — pure deterministic picker. Given the index and an ISO date string, returns one entry.
- **`playAudio(url)`** — wraps the modern `<audio>` element. Falls back to the popup behaviour of `javascript/BatmoAudioPop.js` only if direct playback errors.
- **`bindSearchBox()`** — wires the input, keyboard, click handlers. Glue layer.

Each unit has one job, communicates by argument and return value, and can be tested by isolating it.

### Search index format

`assets/search-index.json` is a single JSON array, one object per entry:

```json
[
  {
    "id": "e13",
    "file": "01.htm",
    "ipa": "ɑcɔkʰɔ",
    "deva": "आचौखौ",
    "en": "side",
    "hi": "तरफ़",
    "cat": "body part term",
    "audio": "audio/acOkho_side.wav"
  }
]
```

Fields are short on purpose — the file ships to every visitor and should stay small. With ~1,200 entries this is well under 200 KB pre-gzip.

Glosses with multiple senses ("clitic, third singular subject (exclusive);") are kept verbatim in `en` and `hi`. Search treats them as a single string.

If an entry has no audio link in its source HTML, `audio` is omitted. If no English gloss, `en` is omitted; same for `hi` and `deva`.

### Index builder

`scripts/build-search-index.mjs` is a one-shot Node.js script. It does:

1. Reads every `lexicon/*.htm` file.
2. For each `<p class="lpLexEntryPara">`, extracts:
   - `id` from the first `<span id="eN" class="lpLexEntryName">`
   - IPA headword (the text inside that span, stripping any homonym index `<sub>`)
   - Devanagari from the next `<span class="lpLexEntryNameGA_in_Sript">`
   - The **first** `<span class="lpGlossEnglish">` content (later occurrences are example glosses, not the main definition)
   - The **first** `<span class="lpGlossHindi">` content (same reason)
   - The first `<span class="lpCategory">` content
   - The entry's main audio link, if any. **Heuristic:** an `<a href="../audio/…">` that precedes the `lpLexEntryName` span within the same `<p>` is the main entry's audio. Audio links that follow `lpLexEntryName` and are adjacent to `lpExample` spans are example-sentence audio and are *not* used here.
3. Cleans up whitespace and trailing punctuation (`;`, `.`).
4. Writes `assets/search-index.json`.

The script is run manually by a maintainer after re-exporting from Lexique Pro: `node scripts/build-search-index.mjs`. Output is committed to git.

### Search algorithm

In `searchIndex(query, index)`:

- Lowercase and trim `query`.
- For each entry, score it against the query:
  - `ipa.startsWith(query)` → score 100
  - `en` token starts with `query` (word-prefix match) → score 80
  - `ipa.includes(query)` → score 50
  - `en.includes(query)` → score 40
  - No match → entry is excluded
- Sort by score descending, then by IPA alphabetically.
- Return top 6.

The matched field and match span are returned alongside each result so the renderer can apply `<mark>` correctly.

`hi` and `deva` are stored for display but not searched, per the scope choice (English + IPA input only).

### Word-of-the-Day selection

`wordOfTheDay(index, dateStr)`:

- Hash the ISO date string (`YYYY-MM-DD`) into a 32-bit integer (simple FNV-1a is fine).
- Filter the index to entries with both an English gloss and audio (so the card is always meaningful).
- Return entry at `hash % filtered.length`.

This is deterministic — every visitor on the same calendar day sees the same word.

### Typography

- **Brand and headwords:** Georgia, serif. Weight 500. Letter-spacing -0.5 to -1px depending on size.
- **Tagline:** Georgia italic.
- **UI elements (search placeholder, browse links, nav, badges):** system sans-serif stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif`).
- **IPA characters:** Georgia renders them adequately; no fallback font needed for v1.

### Layout breakpoints

- **Desktop / tablet (>640px):** centered single column, max width 720px for the hero block (brand + tagline + search), max width 540px for WOTD card. Browse links inline, dot-separated.
- **Mobile (≤640px):** same vertical order, full-width with 22px side padding. Browse links wrap into a 2-column grid with "Lexicon" full-width on top.

### Encoding

All files declared `<meta charset="UTF-8">`. IPA and Devanagari content is stored as UTF-8 in source files. The builder script writes the JSON with UTF-8 encoding and no BOM.

## Behavioural details

- **First load:** `home.js` fetches `search-index.json` immediately on `DOMContentLoaded`. Until the index loads, typing in the search box queues the query; once loaded, results render. With a ~150 KB JSON file on modern connections, the gap is essentially invisible.
- **Debouncing:** input events are debounced 80ms before triggering a search render. Below that threshold the UI lags behind keystrokes; above it the dropdown feels sluggish.
- **Recent searches:** the most recent 5 *opened* entries (not queries) are stored in `localStorage` under key `ga.recent`. Stored as an array of `{id, file, ipa, en}` objects.
- **Audio:** the homepage uses an HTML5 `<audio>` element controlled by JS, not the legacy plugin popup. Files are reached at the same `audio/<filename>.wav` paths the existing pages use. URL-encode spaces in filenames the same way Lexique Pro does.

## Constraints inherited from the existing site

- Spaces in `audio/` and `pictures/` filenames must be URL-encoded as `%20` in HTML attributes and JSON.
- Cross-references between entries are anchored as `NN.htm#eN`; the search-index uses the same convention.
- Lexique-Pro CSS class names (`lpLexEntryName`, `lpGlossEnglish`, `lpGlossHindi`, `lpLexEntryNameGA_in_Sript`, `lpCategory`, etc.) are the parser's anchors. They must not be assumed stable across future Lexique Pro versions — the parser script should fail loudly if the expected classes are absent, not silently produce an empty index.
- Page generator metadata (`<meta name="generator" content="Lexique Pro.3.6">`) is unchanged on existing pages; the new `index.htm` and `about.htm` carry no such tag.

## Testing

This is a static site with no test framework. Manual verification before considering done:

1. Open `index.htm` directly in the browser via `file://` — it loads and the search index fetches successfully (relative paths work locally).
2. Open via `python -m http.server` — same.
3. Type "wat" in the search box: at least three English-gloss matches appear with "wat" highlighted.
4. Type "ɛr": at least one IPA match appears with "ɛr" highlighted in the GA headword.
5. Click an autocomplete row: lands on `lexicon/NN.htm#eN` with the existing fragment-highlight active.
6. Click an autocomplete audio button: audio plays, the row does *not* navigate.
7. Press ↑/↓/Enter: navigates dropdown rows, opens active row on Enter.
8. Open on a mobile-width viewport (≤360px): layout stacks correctly, browse links form a 2-column grid, WOTD card is full-width.
9. Open the same date twice: WOTD is the same word.
10. Open the next day: WOTD is a different word (verify with date override during testing).
11. Click each browse link: lands on the existing index/frameset pages with no broken styling.
12. Click "About" in the top-right: lands on `about.htm`.

## Open questions to resolve during implementation

- **About page copy.** Spec defers exact prose to implementation review.
- **Suggested entries for empty-state "Try" section.** Three handpicked entries; the picks should reflect content of the dictionary and be agreed with the user during implementation.
- **Word-of-the-Day eligibility.** Current rule: must have both English gloss and audio. If too few entries qualify, fall back to "must have English gloss". Confirm during implementation once the index is built and the qualifying count is known.
